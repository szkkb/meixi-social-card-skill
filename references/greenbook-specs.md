# Greenbook Specs (贴图号 / 小绿书 图片消息)

微信公众号「图片消息」的规格、裁切行为与版面配方。
设计真源见根目录 `DESIGN.md`；租户色板见 `brand-presets/`。
模板：`assets/template-greenbook-card.html`。

「小绿书」是坊间叫法，2026 年微信将该功能升级并官方称为「**贴图号**」。两个名字指同一个位。

## 平台规格

证据分级：**已核验** = 直接读到来源原文；**二手一致** = 多个独立二手来源数字一致，
微信官方文档未直接公开。凡标「二手一致」的，首次正式投放前请用一条真实发布自行复核。

| 项 | 值 | 证据 |
|---|---|---|
| 最佳比例 | 3:4，横滑浏览 | 已核验（横滑 + 3:4 展示比例） |
| 画布尺寸 | 1080 × 1440（备选 1242 × 1660） | 二手一致 |
| 图片张数 | 最多 20 张 | 二手一致 |
| 标题 | ≤ 64 字 / 字符 | 二手一致 |
| 描述 | ≤ 1000 字（由 140 扩容而来） | 已核验（扩容事实） |
| 描述实操长度 | 200–300 字 | 二手一致（2026 运营建议） |
| 话题标签 | 2–3 个精准标签 | 二手一致 |
| 消息列表封面 | ≥3 张时取前 3 张拼成 2.35:1 缩略条 | 二手一致 |
| 常读列表 | 首图裁切为 16:9 | 二手一致 |

## 裁切数学（本模板全部构图的起点）

**16:9 常读列表。** 1080 × 9/16 = 607.5 → 608px。居中：(1440 − 608) / 2 = 416。
安全带 = **y 416 – 1024**。带外的内容会被砍掉，所以带外只放可被砍掉的东西。

**2.35:1 三图缩略条。** 三格并排组成 2.35:1，每格宽高比 = 2.35/3 ≈ 0.783，即约 1:1.277。
源图 3:4 = 1:1.333，比格子略窄，所以上下各只切约 30px —— **裁切几乎不构成威胁。**
真正的约束是前三张会**并排出现在同一条里**，必须共享基线横读成一行账。
模板用 `--base-label: 470px` 与 `--base-fig: 880px` 两个变量锁定这两条基线。

验证方法：模板里 `body[data-guides="on"]` 会画出安全带虚线框与缩略条切边，
底部还有两个实测区块（`.band-demo` 复现 16:9 结果，`.strip-demo` 复现三图横读结果）。
**导出前务必把 `data-guides` 改回 `off`。**

## 配方 G01–G07

一套 7 张是默认节奏；20 张上限留给需要逐项拆账或多路线对比的长组。
按 `references/portrait-fill.md` 的节奏要求，一组里至少出现 5 种不同版面形状。

| 配方 | 名字 | 用在哪 | 安全带内放什么 |
|---|---|---|---|
| **G01** | `cover-equation` | 首图变体 A · 纯算式 | 标签 + 超大数字 + 合计线 + 划掉的对照价 + 费用明细 |
| **G02** | `cover-headline` | 首图变体 B · 算式 + 短标题 | ≤8 字得意黑标题 + 数字 + 合计线。**花体字换装位在这张** |
| **G03** | `ledger` | 逐项拆账（体积重 / 关税 / 敏感货各一张） | 短标题 + 3–4 行账目 + 合计线 + 合计数 |
| **G04** | `route-receipt` | 时效即回执 | 路线标签 + 总时效大数 + 分段账目 |
| **G05** | `claim` | 丢件赔付。**红笔在这张用掉唯一一次** | 短标题 + 货值/运费/行业惯例（划掉）+ 本线赔付 |
| **G06** | `qa` | FAQ / 说明页 | 问句标题 + 正文段落，30px 不再缩小 |
| **G07** | `stub-close` | 收尾 / 联系方式 | 一句承诺 + 小程序码 + 域名 |

**首图选哪个变体：**
- 报价可以公开复算 → G01。最不可模仿，但首图没有关键词。
- 需要关键词或需要更强点击钩子 → G02。标题位同时是花体字的落点。
- 报价不透明的租户 → 只能用 G02，且标题必须自己扛住类目认知。

## 硬规则

1. 首图定稿前开 `data-guides="on"`，裁成 y416–1024 后论点必须还完整。做不到就重排，不要缩字。
2. 前三张锁死 `--base-label` / `--base-fig`，横读成一条账。
3. 一组卡里红笔（`.pen-note` / `.pen-strike` 的手写感）至多出现一次。
4. `--edge-blue` 不许离开 `.airmail-edge`。
5. 暖底上的弱化文字一律 `--text-warm`，禁用 `$text-muted #CACCD1`（1.55:1）。
6. 所有数字 `tabular-nums` + 单位 `nowrap`。
7. 卡上每个数字都要能在小程序里被复算出来。做不到的数字不要印。
8. 导出前 `data-guides="off"`。

## 渲染

沿用 `references/production-workflow.md` 的 Playwright 流程，`deviceScaleFactor: 1`，
按 `.board` 元素截图即得 1080×1440。字体走 CDN（ZeoSeven 两个、Google Fonts、Fontshare），
渲染前等 `document.fonts.ready` 并再留 1–1.5s。
离线环境或 CDN 不可达时必须改为自托管字体文件，**不要让它静默回退** ——
得意黑缺失会悄悄退到 Noto Sans SC，成品看起来"只是有点普通"，很难被发现。
渲染脚本应打印 `document.fonts` 中 status === 'loaded' 的 family 列表作为自检。
